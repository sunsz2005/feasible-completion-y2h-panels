# 同时间预算与机制消融：第三轮开发冻结方案

2026-10-23。延续第二轮重点场景：预算 200、训练覆盖下限为参考贪心期望覆盖的 98%。两个来源、各 20 个原种子、3,408 个节点与原 80/20 边分割不变。这是开发分析，不重置原首次评价，也不是独立确认。

技术修订记录：首次运行在首个分割落盘时因 NumPy int64 不能直接 JSON 序列化而终止，没有保存任何分割成绩。将角色变化计数显式转换为 Python int 后重跑；算法、随机种子、时间政策和比较对象不变。初始哈希清单另存 lock_initial_serialization_failure.json，修订后重新冻结。

## 同时间比较

每个分割先计算共享覆盖顺序及确定性角色基准，计为共同预处理成本并计入所有方法总耗时。新构造随后独立计时，以此次实际构造耗时作为两类基线各自的搜索预算。两类基线采用同一机器顺序运行，按种子交替执行顺序。不计测试评价耗时。

- 固定面板多起点：保持原覆盖面板不变，随机生成等量角色划分，用完整角色单交换优化；只按训练割边保留最佳可行解。
- 多起点联合搜索：从原覆盖基准或迄今最佳解出发，交替采用长度 2/4/8 的可行扰动，之后进行相同的角色及选内/选外单交换；替换检查训练收益最高的 128 个候选。扰动的候选节点一半从度数前 1,000 节点抽取、一半从全候选抽取，均保持不同角色并检查覆盖。不使用新构造作为初始化，以保持比较独立。
- 搜索截止前留 0.01 秒余量，检查动作和候选循环中的截止时间。允许原子操作开销：超时不超过 max(0.02 秒，5% 搜索预算) 记为时间合格，实际耗时和超时全部保留。不删除时间不合格分割，另报其结果并明确不能据此断言严格同时间优势。
- 墙钟截止导致起点数可能随机器负载变化。保存面板、次数、耗时和全部成绩。所有选择仅用训练目标，禁止按测试分数挑起点。

## 消融

1. 去角色增益：保留相同可行完成集合、覆盖条件、16 个选入和 8 个换出候选，将选入排序改为度数与 ID，不考虑已承诺对侧边数；末尾仍给予与完整构造相同的角色优化。它检验角色感知的选点价值，不要求构造阶段的任意角色标签本身成为最终角色。
2. 去覆盖守门：调用同一新构造，覆盖下限置零，其他设置不变。报告测试命中与覆盖下降，不把不满足覆盖条件的面板纳入同覆盖条件优胜比较。

完整构造、两类同时间基线、原覆盖基准、两项消融共六方法，合计 240 条面板记录。独立核验割边、覆盖、互斥预算、扰动结果和分割哈希。针对每类基线和消融分别报告成对差中位数及正/零/负次数，不事后选择最弱基线作为唯一对照。原覆盖基准用于前后核对。

## 解释重点

主问题是新构造在控制计算投入后能否保留筛查机会收益。分别解释角色感知选点、覆盖约束、面板内部互作边数量与跨角色安排的作用。两张网络不能支撑通用适用性预测；所有内部测试结果均已属于开发记录。若同时间搜索缩小差距，应如实改写贡献范围，不更改该轮时间预算或比较对象。
